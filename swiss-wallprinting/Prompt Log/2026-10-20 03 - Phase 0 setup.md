## Decisions

- **Vite+ manages only pnpm.** The installer asked whether Vite+ should manage Node.js and package managers. The author's plan says "pnpm provisioned by Vite+", so only pnpm is managed; the system Node and npm are not changed.
- **Hand-written scaffold**, not `create-next-app`: the folder already had files (`Assets/`, the vault, `CLAUDE.md`), and `create-next-app` refuses such a folder.
- **TypeScript 6.0, not 7.0.** Next.js uses the TypeScript JavaScript API for its build check; TypeScript 7 is the Go version. `vp check` already type checks with the TypeScript 7 toolchain (tsgolint).
- **pnpm build scripts off** for `@parcel/watcher` and `@swc/core` (both come from next-intl and have prebuilt binaries).
- **No domain routing yet.** next-intl needs unique locales per domain, so the plan's `.ch` / `.com` split cannot work as written. Two options are in [[Development Plan#3. Information architecture]]; decide in Phase 7.
- **Route group `(pages)`** with `dynamicParams = false`: only the four locales match the pages, so `/missing.txt` gets the global 404 instead of Next's default page.
- **Mock guard as a script before `next build`**, not in `next.config.ts`: it works on every host and is easy to test.
- **Lint rule `vitest/valid-expect` allows 2 arguments**, because Vitest supports `expect(value, message)`.
- **`vp config --no-agent`** in `prepare`, so that Vite+ does not edit `CLAUDE.md`.
